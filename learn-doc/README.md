# llama.cpp 学习路线

这里是基于 `v1.0.0` tag 整理的入门路线。所有路径和行号都对应这个 tag,换版本后行号可能偏移,但文件名和结构基本稳定。

> 分支说明:本仓库的 `v1.0.0-learn` 分支是个人学习分支,不向上游提 PR,也不同步上游代码。
> 因此源码里可以直接写大段中文注释、改实验代码、仓库内的行号以本分支为准。
> 上游 `AGENTS.md` 里关于注释风格和 AI 使用的约束不适用于本分支的改动。

## 先想清楚你要哪一半

llama.cpp 这个仓库其实是两个项目叠在一起:

| 部分 | 目录 | 负责什么 |
|---|---|---|
| ggml | `ggml/` | 张量库 + 各种硬件后端,把数学运算跑到 CPU/CUDA/Metal 上 |
| llama | `src/` `common/` `tools/` | 读模型、管理 KV cache、拼图、采样、聊天模板、HTTP 服务 |

大多数人只需要懂上半部分(llama),只有想改性能或加新硬件后端时才需要钻 ggml。

## 几条原则

**别线性读大文件。** `src/llama-context.cpp` 有 5185 行,`src/llama-vocab.cpp` 有 4853 行。这些文件是按功能分块累积出来的,从头读到尾会迷路。正确做法是拿一个调用栈或一个功能点,跳着读相关函数。

**先看现象再看代码。** 每一步都先跑一遍相关的命令行工具,知道"正常"长什么样,读代码时才有对照。

**用测试当文档。** `tests/` 里几乎每个子系统都有对应测试,想知道某个函数的确切语义,测试比注释可靠。比如 `tests/test-sampling.cpp`、`tests/test-chat.cpp`。

**改代码前先搜 issue。** 这个仓库的维护者对改动非常挑剔,大改动不先讨论基本会被关。学习阶段建议只在自己的 fork 上动手。
